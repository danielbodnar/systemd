# systemd-networkd

An orchestrator hides three things behind a network name: an address range, a way for members on different hosts to reach each other, and a way for clients to reach published ports. systemd separates them: `systemd-networkd` manages links, bridges, and tunnels from `.network` and `.netdev` files; the service manager binds ports through `.socket` units or lets the process bind them under `SocketBindAllow=`; resolution is `systemd-resolved`'s job (see the `systemd-resolved` skill). Every one of those is a decision here, because a wrong guess about a subnet or a transport is the kind of mistake that takes a site down.

## Decisions it raises

- `networkd.subnet.<network>` (value, CIDR) for every application network: the range it uses on the systemd hosts. The source's IPAM subnet is the default and the evidence; for a macvlan or ipvlan network the source's `ip_range` is the default instead, because the rest of the segment belongs to the site. Change it when the range collides with the site.
- `networkd.domain.<network>` (value, name, default `_dhcp`) for every application network: the local domain under which the host resolves the DHCP leases of the zone bridge (`LocalLeaseDomain=`), which is what the shipped `80-container-vz.network` uses.
- `networkd.transport.<network>` (choice) for every overlay whose members land on more than one host: `vxlan-wireguard` (default when the source overlay was encrypted), `vxlan`, `wireguard` (routed, no L2), or `underlay` (the site's routers carry the bridge subnets). An unencrypted source overlay has no default: pick one.
- `networkd.vni.<network>` (value, port format) for every such overlay: the VXLAN network identifier. The default is the network's 1-based position among the application networks sorted by name, so two overlays never share a VNI.
- `networkd.wireguard.subnet.<network>` (value, CIDR) for every such overlay: the range the WireGuard tunnel addresses come from, one address per host in the order of the host names. The default is `100.64.<position>.0/24` from the RFC 6598 shared address space, chosen by the same position as the VNI.
- `networkd.wireguard.port.estate` (value, port, default 51820) when any overlay spans hosts: the base UDP port. The network at position `p` listens on the base port plus `p - 1`, so several tunnels on one host never collide.
- `networkd.wireguard.endpoint.<host>` (value, IPv4) for every host an overlay lands on: the address the other hosts reach it at, for the WireGuard endpoint or the VXLAN underlay. The default is the host's first probed address, else the inventory node's address; there is no default when neither exists.
- `networkd.uplink.<host>` (value, path, no default) raised on the next plan run after a transport chose `underlay`: the `.network` file that configures the host's uplink, so the routes to the other hosts' slices can be rendered as a drop-in for it.
- `networkd.parent.<network>` (value, name) for every macvlan or ipvlan network: the host link the interfaces attach to. The default is the parent the source recorded; there is none when the source recorded no parent.
- `networkd.zone.<service>` (choice) for every service that is a member of at least one application network: which network the service attaches to when it runs as a machine, one option per network plus `host` for the host's network namespace. The default is the first network in the service's list. The machined component reads it to write `Zone=` or `Private=no`.
- `networkd.publish.<service>.<port>-<protocol>` (choice) for every published port: `host` (default for host-mode ports), `socket`, `external-lb`, or `dns-rr`. An ingress-mode port has no default: the routing mesh is gone, so say what replaces it.

## What it renders

- For a plain service: `SocketBindAllow=<proto>:<port>` and `SocketBindDeny=any`, or a `<unit>-<port>.socket` when the port is socket-activated. Published ports that differ from the container port, and instances that share a host, are noted.
- For a machine attached to an overlay or bridge network: `25-migration-vz-<network>.network` for the zone bridge `vz-<network>` that `systemd-nspawn` creates for `Zone=`, with the host's gateway address inside the decided range, `DHCPServer=yes` with a pool inside the range, masquerading unless the source network was internal, `LocalLeaseDomain=` from the domain decision, and one `[DHCPServerStaticLease]` per machine with an address derived from the range and a MAC derived from the machine name. The machine's `systemd-nspawn@.service` drop-in gets `Environment=SYSTEMD_NSPAWN_NETWORK_MAC=` with that MAC, and its `.nspawn` file gets one `Port=` per published port. A network that spans hosts is split into equal slices, one per host, so gateways, leases, and pools never collide.
- The transport between the hosts of a multi-host overlay, from the transport decision: `25-migration-vx-<network>.netdev` and `.network` (VXLAN enslaved into the bridge, `Remote=` for two hosts or one `[BridgeFDB]` flood entry per peer for more), `25-migration-wg-<network>.netdev` and `.network` (the WireGuard mesh: `PrivateKey=@network.wireguard.private.25-migration-wg-<network>` and `PublicKey=@network.wireguard.public.<host>` are credentials the operator supplies, never values in the file; routed mode adds `AllowedIPs=` and `[Route]` for each peer's slice), or a `[Route]` drop-in for the decided uplink when the site's network carries the slices. `/etc/sysctl.d/80-migration-forwarding.conf` enables IP forwarding only for the routed transports. `install.sh` runs `networkctl reload` after copying the files.
- For a machine attached to a macvlan or ipvlan network: `25-migration-mv-<network>.netdev` (the host's own interface on the parent, so it can reach the machines), `25-migration-mv-<network>.network` with the host's address from the decided range, `25-migration-parent-<network>.network` that stacks the interface on the decided parent link, and `MACVLAN=` or `IPVLAN=` in the machine's `.nspawn` file. No DHCP server runs on the site's segment; the address each machine should configure is derived like a lease and listed in the notes and the hosts fragment.
- Every rendered `.network`, `.netdev`, and drop-in is checked against the directive catalogue, and every basename is recorded in `expected.json` under `networks`.

`references/zone-bridge.md` explains the bridge, the address plan, the MAC derivation, and the exact file shapes of the three transports.
